# 信息提取报告模板字段与渲染规则说明

## 1. 文件职责

- `information_extraction_v1.docx`：生产模板。只保存固定结构、标量槽位、每个动态区域的一个原型行或原型段落。
- `information_extraction_v1.sample.docx`：视觉样例。使用“上界路 K46+500 上跨车行桥”数据展示多条建议、多条病害及多段专业文稿的实际效果。
- `template_fields.json`：字段、位置、动态区域及编号规则的机器可读契约。
- `style_spec.py`：复制动态行或段落时必须显式维持的版式参数。DOCX母版本身仍是样式真源。

生产模板不得冻结建议、病害、成因或处置建议的数量。

## 2. 固定结构

模板固定保留以下标题与章节顺序：

1. 报告总标题
2. `1、简要信息`
3. 三列概要表
4. `2、详细信息`
5. `（1）详细结论`
6. 四个详细结论段落槽位
7. `（2）建议明细`
8. 四列建议表
9. `（3）病害列表`
10. 七列病害表
11. `病害成因`
12. `处置建议`
13. `安全影响`

所有固定标题均设置“与下段同页”。其中模板内部段落文本是`病害列表`，Word通过自动编号显示为`（3）病害列表`。渲染器必须保留该段落及其`numPr`，不得删除、重建、清空或覆盖。

## 3. 标量字段

标量字段直接替换，不复制段落或表格行：

| 字段 | 占位符 | 内容要求 |
|---|---|---|
| 报告标题 | `{{report_title}}` | Pipeline输出完整标题，例如`上界路 K46+500 上跨车行桥·无对比年度的信息提取报告` |
| 桥梁名称 | `{{bridge_name}}` | 桥梁全称 |
| 报告日期 | `{{report_date}}` | 保持报告中的年月或日期精度 |
| 总体评分/等级 | `{{overall_score}}`、`{{overall_grade}}` | 不自行推算缺失值 |
| 上部结构评分/等级 | `{{superstructure_score}}`、`{{superstructure_grade}}` | 同上 |
| 下部结构评分/等级 | `{{substructure_score}}`、`{{substructure_grade}}` | 同上 |
| 桥面系评分/等级 | `{{deck_system_score}}`、`{{deck_system_grade}}` | 同上 |
| 上一次总体评分/等级 | `{{previous_overall_score}}`、`{{previous_overall_grade}}` | 首次检测或报告明确不存在时填`无` |
| 病害发展趋势 | `{{defect_development_trend}}` | 无对比数据时填`无`；抽取失败时填`未提取到` |
| 总体结论 | `{{overall_conclusion}}` | 概要表中的简短总体结论 |
| 主要风险点 | `{{major_risks}}` | 概括突出病害及直接风险 |
| 建议汇总 | `{{recommendations_summary}}` | Pipeline生成完整文本，省略数量为0的类别 |

建议汇总示例：

```text
1条立即处置、5条尽快维修、2条预防性养护
```

不得在模板中写死“尽快维修”和“预防性养护”两个类别，也不得输出`0条某类别`。

## 4. 四段详细结论

详细结论固定为四个段落槽位，但文稿由Pipeline确定性生成：

1. `{{score_and_grade}}`：本次总体评分、总体等级及各分部评分和等级。
2. `{{history_and_defects}}`：是否存在历史对比；有对比时说明上次评分、等级及病害发展；随后概括本次病害。
3. `{{current_structure_state}}`：依次归纳上部结构、下部结构和桥面系的当前状态。
4. `{{comprehensive_judgement}}`：主体结构状态、突出病害、风险、处置重点及养护要求。

这四个槽位是固定段落，不属于动态数组。Renderer只替换文本，不删除或复制段落。

## 5. 动态表格

### 5.1 建议表

模板只保留表头和一行原型：

```text
{{recommendation.index}}
{{recommendation.category}}
{{recommendation.content}}
{{recommendation.location}}
```

渲染顺序：

1. 对结构化建议去重、排序。
2. 从1开始连续编号，不采用原始报告中不稳定或缺失的序号。
3. 深复制原型行及其完整`trPr`、`tcPr`、边框、列宽、单元格边距和段落格式。
4. 每条建议填入一行；同一建议的多段文字合并在`recommendation.content`单元格中，不生成空序号行。
5. 全部填充后删除原型行。
6. 建议数量为0时，删除原型行，仅保留表头。

建议内容左对齐，其余三列居中并垂直居中。所有行禁止跨页断裂，表头跨页重复。

### 5.2 病害表

模板只保留表头和一行原型：

```text
{{defect.index}}
{{defect.location}}
{{defect.type}}
{{defect.description}}
{{defect.is_new}}
{{defect.previous_status}}
{{defect.development_degree}}
```

渲染顺序：

1. 上游完成病害去重和观察项组织，Renderer不擅自截断或删减病害。
2. 最终病害序号从1开始连续生成。
3. 一条病害包含多条连续观察时，可生成多行，并对相同`defect.index`的“序号”单元格做纵向合并。
4. 只允许合并连续、序号相同的第一列；不得自动合并病害部位、病害类型或其他列。
5. 填充结束后删除原型行；病害数量为0时仅保留表头。
6. 病害描述列左对齐，其余列居中并垂直居中。
7. 表头跨页重复，普通行禁止跨页断裂。

病害数量异常属于抽取与去重层问题。Renderer可以记录警告，但不得静默截断1000条病害为固定上限。

## 6. 动态正文段落

### 6.1 病害成因

模板只保留一个原型段落：

```text
{{cause.text}}
```

Renderer按数组顺序复制段落，并添加中文编号`（1）`、`（2）`……。成因文本本身不携带编号。数量为0时删除原型段落，但保留“病害成因”标题。

生成优先级：报告明确原因句 > 病害知识规则 > 受约束LLM补全。不得把处置措施改写成病害成因，也不得把可能原因写成无证据的确定事实。

### 6.2 处置建议

模板只保留一个原型段落：

```text
{{treatment.text}}
```

Renderer复制并添加中文编号。处置建议原则上与建议明细逐条对应，内容来自确定性结构化建议，不由LLM自由改写事实。数量为0时删除原型段落，保留标题。

### 6.3 安全影响

模板只保留一个原型段落：

```text
{{safety_impact.text}}
```

Renderer按数组复制，不自动添加编号。每段按病害组或结构部位组织；最后一段可作为综合判断。数量为0时删除原型段落，保留标题。

## 7. 占位符替换要求

Word可能把一个占位符拆成多个Run。Renderer不得只执行：

```python
for run in paragraph.runs:
    run.text = run.text.replace(...)
```

推荐做法：

1. 在段落或单元格的完整文本范围内定位占位符。
2. 建立字符位置到Run的映射，跨Run替换；或在确认该段只有一个槽位时清空内容并按原型首个Run格式重新写入。
3. 动态行/段落必须先深复制原型，再写入内容，避免丢失字体、边框、缩进和分页属性。
4. 渲染结束后扫描全文，任何残留`{{...}}`均视为失败。

## 8. 缺失值与空数组

统一口径：

- 报告明确表示不存在、首次检测无历史数据：`无`。
- 理应存在但未抽取到：`未提取到`。
- 建议类别数量为0：在`recommendations_summary`中省略该类别。
- 动态数组为空：删除原型行或原型段落；固定表头和固定章节标题保留。

不得把`无`与`未提取到`混用，否则会掩盖抽取失败。

## 9. 渲染器不得执行的操作

- 不从空白`Document()`重新搭建文档。
- 不重建、覆盖或删除固定标题。
- 不按固定7条建议、9条病害或5条成因循环。
- 不依赖原始`index`直接生成最终序号。
- 不在Renderer中做病害去重、结论推理或LLM改写。
- 不因为表格过长而静默截断。
- 不重新计算模板列宽。

## 10. 建议的数据流

```text
RawExtraction
→ ReportFacts
→ NarrativeSections
→ SubmissionDocument
→ template_renderer
→ DOCX
→ DOC转换
```

`SubmissionDocument`至少应包含：

```text
scalars
score_and_grade
history_and_defects
current_structure_state
comprehensive_judgement
recommendations[]
defects[]
causes[]
treatments[]
safety_impacts[]
```

Renderer只负责把该对象映射到模板，不临时决定文稿内容。

## 11. 冻结验收

每次修改模板或渲染器后至少检查：

1. 固定标题顺序未变，`（3）病害列表`仍正常显示。
2. `病害成因`、`处置建议`、`安全影响`均与下段同页。
3. 模板中建议表和病害表均只有“表头 + 1行原型”。
4. 三个动态正文区域均只有一个原型段落。
5. 不存在`_1`、`_2`等固定编号占位符。
6. 不存在把生成说明写入占位符名称的情况。
7. 建议汇总仅使用`{{recommendations_summary}}`。
8. 表头重复、表格行禁止跨页断裂、固定列宽仍有效。
9. DOCX转DOC后标题、表格和分页不漂移。
10. 渲染完成后不存在任何残留占位符。
