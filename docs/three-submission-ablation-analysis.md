## 3. 等级体例回查（本轮新实锤，推翻"等级映射错误"判断）

### 3.1 报告原文证据

**太平水库大桥**（提取值：super 86.10→D级、deck 85.75→D级，被误判为"等级映射错"）：

```
报告原文：
"经计算桥面系BCIm=85.75；BSIm=min（100-MDPh）=64.38，桥面系结构状况评定为D级；"
"经计算上部结构BCIs=86.10；BSIs=min（BCIsi）=62.72，上部结构结构状况评定为D级；"
```

**大山村互通Ⅱ号桥**（提取值：deck 78.73→C级、super 80→B级）：

```
报告原文：
"经计算桥面系BCIm=78.73，BSIm=67.61，评定为C级；"
"经计算上部结构BCIs=80，BSIs=min(BCIsi)=80，评定为B级；"
```

### 3.2 结论：报告等级按 BSIm/BSIs（分项最低值）评定，提取器完全正确

```
评定规则（CJJ 99-2017 重庆地区实施）：
  分项结构状况等级 = f(BSIm = min(分项各构件指数))   ← 报告正文如此评定
  而非 f(BCIm = 加权总评分)                          ← 我此前误用的通用标准

太平水库：BCIm=85.75（表面 B 级）但 BSIm=64.38 → 报告评 D 级 → 提取 D 级 ✅ 正确
```

**"78/282 与通用映射不符"不是提取错误，是报告体例**。我此前"等级映射 28% 错误率 = 正确率冻死原因"的判断**作废**。

### 3.3 遗留的新假设（可实验验证）

```
平台若按通用标准（A≥90/B80-89/C70-79/D60-69）校验等级，
则"86.10→D级"会被平台判为等级错误 → 正确率冻死
验证方法：下一轮把等级改为通用映射值（86.10→B级）提交，
          与保留报告值（D级）做 A/B，看正确率是否变化
```

## 6. 平台分项反推

### 6.1 简要正确率：28% 三次冻死

三版正确率完全一致 → 正确率评的字段里，三版从未变化的部分才是关键：

```
三版都不变：
① 评分/等级字段（同一 extractor，按报告 BSIm 体例提取——提取正确）
② trend：三版全无真值（0/92）
③ 总体结论内容：三版各不相同（31官方/32摘录/28无开头）→ 不是正确率主因？
④ prev_grade：31 全空 vs 32/28 有 56 份 → 有值没提正确率 → 文件名值可能不被认可
```

**候选解释（按可能性排序）**：
1. **平台按通用标准校验等级**：86.10→D级（报告体例）被平台判"等级错误" → 等级字段系统性失分 → 正确率冻死。**可实验验证**（见 3.3）
2. **trend 全无**：若 trend 计入正确率，0/92 全错拖低正确率
3. **prev_grade 文件名值不被认可**：32/28 版 56 份有值但正确率没升 → 平台期望正文历史值

### 6.2 一致性（26→29→24、27→31→26）：严格跟随内容量

| 版本 | OC 字数 | causes 条数 | DC 段数 | safety | 一致性 |
|---|---|---|---|---|---|
| 32_deepseek | 数百-千字 | ~4.7 | 4 段 88 | 3-4 条 | **29%/31%** |
| 31_composer | ~100 字 | ~2.8 | 4 段 92 | 2-4 条 | 26%/27% |
| 28_v7 | ~90 字 | ~0.3 | 3 段 84 | 2 条套话 | 24%/26% |

**结论：平台一致性对"文本内容量"强敏感——有内容（即使格式错）> 无内容（格式对）**。28_v7 的"没有证据就不写"导致内容骤减，一致性直接跌到三次最低。

### 6.3 逻辑性（53→58→46、37→37→34）：同样跟随内容量

32 内容最完整 → 逻辑性最高；28 内容残缺（DC 缺段、causes 空）→ LLM 评审判定"没写完"，逻辑性最低。

## 7. 核心发现（消融最终结论）

### 发现 1：31_composer 是"格式最正确"版本，分却最低（31.21）
- OC 100% 官方开头、DC 100% 四段、RP 病害+后果格式全对
- 但分最低 → **格式对齐不是提分主因**（推翻此前判断）
- 分低原因：prev_grade 92/92 空、trend 全无、OC 内容过短（~100 字）

### 发现 2：32_deepseek 是"内容最满"版本，分最高（32.80）
- OC 全摘录（格式最差）依然最高 → **平台给"内容量"基础分，对格式错容忍**

### 发现 3：28_v7 是"证据最干净"版本，分最低（28.52）
- causes 0 条、DC 缺段、safety 套话 → **空字段惩罚 > 格式错惩罚**

### 发现 4：正确率冻死的真凶不是等级映射（报告体例），是"值不被认可"或"字段全缺"
- 等级提取正确（BSIm 体例），但平台可能按通用标准判错 → 待 A/B 验证
- trend 三版 0/92 全缺、prev_grade 文件名值无效 → 正确率第二嫌疑

### 发现 5：建议摘要/明细三版一致（误判修正）

### 发现 6：正确策略 = "内容优先 + 值正确"，格式次之
```
31 版证明：格式全对 ≈ 无收益（31.21）
32 版证明：内容满 ≈ 有收益（32.80）
28 版证明：内容空 ≈ 负收益（28.52）
→ 叙述字段必须有内容（正文真句），且评分/等级/趋势的值必须被平台认可
```
