# 效率精简规范（去审计、去扫描、去重复防泄漏）

> 目的：砍掉不直接通向"86 份正式分数 / 最终交付包"的工程动作。
> 适用：所有 worker（结构化线、RAG+LLM 线）及所有覆盖包验证流程。

---

## 一、明确去除（不再执行）

### 1. 反复审计（audit）

| 原动作 | 去除方式 |
|---|---|
| 每个覆盖包进来手工核对产物（解压→diff→重抽→对比声明） | ❌ 不再做逐包人工核对 |
| Gold 门控复核（2761 条 vs 误杀）每轮重跑 | ❌ 只在 v3 那种"改了病害判定"的改动时跑一次，之后不跑 |
| 每轮生成 row-evidence-inventory / field-summary / review-key-fields 等审计清单 | ❌ 不生成，不维护 |
| 86 份真实重抽+评分每轮跑两遍（回放一遍+重抽一遍） | ❌ 只跑真实重抽一遍，回放不再做 |

**保留的唯一审计**：正式 benchmark 落盘（score.json / aligned-predictions / errorbook），因为它是交付必需。

### 2. API Key 扫描

| 原动作 | 去除方式 |
|---|---|
| 每轮 API_KEY_LITERAL_SCAN=0 | ❌ 不再执行 |
| 扫描结果写入每轮汇报 | ❌ 不再写入 |

**理由**：key 只进环境变量、不进代码/Git/日志这一约定本身不变；但"每轮再扫描验证一遍"是重复劳动。信任约定，不反复验证。

### 3. 重复防泄漏检查

| 原动作 | 去除方式 |
|---|---|
| 每建一个索引都验证"目标样本自身 Gold 标签数量=0" | ❌ 不再逐索引验证 |
| fit-only 索引的 split 过滤逻辑每轮人工复核 | ❌ 不再复核（逻辑已冻结在 build 脚本中） |
| 候选反推检查（gold_row/gold_anchors 不得用于选候选） | ❌ 不在每轮核查 |

**保留的唯一防泄漏**：构建脚本里 `exclude_sample_id` / `fit_only` 参数本身（写死的代码逻辑），运行时不验证。

---

## 二、保留（必要，不动）

| 机制 | 理由 |
|---|---|
| 字段级 fallback 到 Baseline | 防 LLM 掉分的核心保险（12-030 已实测有效） |
| 评分门禁 + pytest 全绿 | 防回退的唯一量化手段 |
| 共享公共索引（fit Gold + 知识卡只嵌一次） | 86 份评估从 ~14h 降到 ~1.5h 的关键 |
| 86 份真实重抽评分 | 唯一正式分数来源 |
| 锁定字段不变检查 | 防 LLM 改结构字段 |

---

## 三、优化后（只做一次或自动）

| 项 | 新规则 |
|---|---|
| 索引构建 | 公共部分一次构建、全局共享；每样本只嵌当前报告证据（~30s） |
| row gate | 用确定性预筛（ambiguous 样本/照片尾缀残留/同键多行 → 每份 3-8 行）替代等 diagnostics 升级 |
| 审计命令 | 合并成一条：`重抽 86 份 + 评分 + 落盘 benchmark`，覆盖包进来只跑这一条 |
| worker 使用 | 只用于 86 份批跑分块或实验性代码隔离；汇总/核查/评分/索引直接本会话跑 |

---

## 四、去审计后的验证责任

不再逐包人工核对，改为**唯一验收动作**：

```powershell
python -m pytest -q                    # 全绿（当前 299 passed）
python scripts/run_round2_benchmark.py # 86 份真实重抽 + score.json 落盘
```

**通过标准**（三条保护线 + 总分不回退）：
- 处置建议 ≥ 4.86
- 病害列表 ≥ 24.64
- 建议明细 ≥ 11.84
- micro 总分 ≥ 67.21（当前基线）

不达标才需要人工介入定位；达标即接受，不再逐字段核对。
