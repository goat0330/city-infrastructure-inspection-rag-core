## 一、为什么"简要信息正确率 28%"一直没修好（必须先理解）

### 1.1 四版平台分 + 正确率全部 28% 冻死

| 版本 | 管线 | 简要正确率 | 等级取值口径 |
|---|---|---|---|
| 31.21 | Composer 组织 | 28% | 报告体例 |
| 32.80 | DeepSeek narrative | 28% | 报告体例 |
| 28.52 | v7 纯规则 | 28% | 报告体例 |
| 37.92 (v8) | Qwen narrative | 28% | 报告体例 |

### 1.2 根本原因：等级口径从未被实验过

```
所有版本的等级都"忠实于报告原文"提取：
  太平水库报告写"上部结构结构状况评定为D级" → 我们提取 D级
  但 86.10 分按通用标准（A≥90/B80-89/C70-79/D60-69）应该是 B级

报告等级按 BSIm（分项最低值）评定，不是按总评分映射：
  太平水库 BCIs=86.10 但 BSIs=62.72 → 报告评 D级（忠实提取）

平台若按通用标准判"评分-等级对"（86.10 必须配 B 级才算对）
→ 我们的等级字段系统性错 → 正确率冻死
```

**为什么一直没人修**：因为"忠实报告"看起来是安全的（报告原文就是 D 级），没人敢改成通用映射（怕改错）。但平台可能就用通用标准。**唯一验证方式 = A/B 实验**，而 A/B 一直没做过。

### 1.3 本地实测证据（我方已跑，直接采信）

```
  太平水库大桥  superstructure 86.10 → D级（通用应 B）
  太平水库大桥  deck           85.75 → D级（通用应 B）
  官方院子桥式   superstructure 92.5  → B级（通用应 A）

  尹家湾大桥    substructure  95.53 → B级（通用应 A）
```

## 三、云端 Worker 任务（全部代码级，不依赖 92 份数据）

### 任务 1【第一刀·最高优先】：等级映射开关（A/B 可切换）

**目标**：让提交方可一键切换"报告体例等级"和"通用映射等级"两种口径，分别出包提交对比正确率。

**改动位置**：
- 新建 `src/extraction/grade_mapping.py`（或加入 `src/extraction/summary/extractor.py`）

**实现要求**：
```python
# 1) 通用映射函数（纯函数，可单测）
def grade_from_score(score: float) -> str | None:
    """A≥90 / B 80-89 / C 70-79 / D 60-69 / E<60"""
    if score >= 90: return "A级"
    if score >= 80: return "B级"
    if score >= 70: return "C级"
    if score >= 60: return "D级"
    return "E级"

# 2) 开关（环境变量，默认保持现状）
GRADE_MODE = os.getenv("GRADE_MODE", "report")
#   "report"  = 提取报告原文等级（当前行为，A 组）
#   "generic" = 按评分通用映射覆盖等级（B 组，仅当评分存在时）

# 3) 应用点：summary 组装处（overall/super/sub/deck 四组）
#    仅当 GRADE_MODE=="generic" 且 score 非"无"时，用 grade_from_score(score) 覆盖等级
#    无评分时等级保持"无"（不凭空生成）
```

**单元测试（云端可跑，必须写）**：
```python
test_grade_from_score_boundaries: 90→A、89.99→B、80→B、79.99→C、70→C、60→D、59.99→E
test_generic_mode_overrides_report_grade: 86.10 + mode=generic → "B级"
test_report_mode_keeps_extracted_grade: mode=report → 保持"D级"
test_generic_mode_no_score_keeps_none: score="无" → 等级"无"
test_four_groups_all_affected: overall/super/sub/deck 四组都生效
```

**验收（云端）**：上述单测全绿；不破坏现有 report 模式行为（默认）。

### 任务 2【第二刀·备选】：摘要官方句式对齐

**目标**：若等级 A/B 后正确率仍不动，用于验证"语义评审"假设。本地已确认当前摘要句式与官方模板有差异：

```
  太平水库大桥上部结构主梁存在多处渗水泛碱、露筋、剥落、脱落等病害；下部结构有较为明显…
官方模板（赛题一文档）：
  本次定检结果表明，桥梁上部结构{病害}；下部结构{病害}；桥面系{病害}。
要求：
  开头固定"本次定检结果表明，桥梁"；部位序 上→下→桥面系；病害用顿号、部位用分号
```
**改动位置**：`src/extraction/text_sections.py`（overall_conclusion 生成处）

**2b. 趋势（当前机械前缀）**
```
当前（实测）：
  上部结构:新增病害:局部渗水泛碱,部分主梁破损露筋。;下部结构:无;桥面系:…
要求：
  官方"与上一次定检相比，{部位}{病害}，{发展描述}"；去"新增病害:无"、半角冒号
```

**2c. 风险点（确定性跑为空，narrative 跑有内容）**
```
当前确定性跑：主要风险点 = "无"
要求：病害+后果成对（"{病害}，{后果}；"）—— 从报告评估结论章节提取后果，
      无证据保持"无"（不得编造）
```

**改动位置**：`src/extraction/text_sections.py` / narrative 的 risk_points 生成

**单元测试**：句式开头断言、部位顺序断言、趋势无机械前缀断言。
